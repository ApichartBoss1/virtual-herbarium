# Virtual Herbarium

คลังพรรณไม้ดิจิทัลของหอพรรณไม้ คณะวิทยาศาสตร์ มหาวิทยาลัยนเรศวร
พัฒนาเป็นโครงงานปริญญาตรี คณะวิทยาศาสตร์ มหาวิทยาลัยนเรศวร

เว็บจริง: <https://virtual-herbarium.vercel.app>

## ฟีเจอร์หลัก (Features)

- **ค้นหาและกรอง**: ค้นหาด้วย PNU, ชื่อวิทยาศาสตร์, วงศ์, ผู้เก็บ หรือสถานที่ และกรองตามวงศ์ กลุ่มพืช และผู้เก็บตัวอย่าง ตัวกรองอยู่ใน URL จึงแชร์ลิงก์ได้
- **หน้ารายละเอียดพร้อมข้อมูลจาก GBIF**: แสดงลำดับชั้นทางอนุกรมวิธาน ชื่อสามัญ จำนวนบันทึกทั่วโลกและในประเทศไทย แผนที่การกระจายพันธุ์ และรูปถ่ายพร้อมเครดิตและสัญญาอนุญาต
- **แผนที่รวม** (`/map`): หมุดของทุกรายการที่มีพิกัด จัดกลุ่มอัตโนมัติ และใช้ตัวกรองชุดเดียวกับหน้ารายการพรรณไม้ หมุดพิกัดโดยประมาณ (จากชื่อสถานที่) แสดงต่างจากพิกัดที่บันทึกเอง พร้อมคำอธิบายสัญลักษณ์
- **QR code และพิมพ์ป้าย**: ทุกรายการมี QR code ลิงก์ไปยังหน้ารายละเอียด และผู้ดูแลพิมพ์ป้ายติดตัวอย่าง (A4 หน้าละ 8 ป้าย) ได้ตามช่วง PNU หรือตามรายการที่เลือก
- **ตรวจชื่อวิทยาศาสตร์กับ GBIF**: ตรวจในหน้าเพิ่มและแก้ไขรายการ บอกได้ว่าชื่อสะกดผิด เป็นชื่อพ้อง หรือไม่พบ
- **นำเข้าข้อมูล**: นำเข้าไฟล์ Excel (.xlsx) หรือ CSV ทุกชีตรวมกัน คัดแถวว่าง PNU ผิด/ซ้ำ/มีในระบบแล้ว และข้อมูลไม่ครบก่อนบันทึก มีรายงาน Excel ของแถวที่ถูกคัดออก และอัปโหลดรูปหลายไฟล์พร้อมกัน (จับคู่กับรายการตาม PNU ในชื่อไฟล์)
- **เติมพิกัดอัตโนมัติ**: ค้นพิกัดโดยประมาณจากชื่อสถานที่ให้รายการที่ยังไม่มีพิกัด บันทึกเป็น “โดยประมาณ” พร้อมรัศมีความคลาดเคลื่อน
- **รายงานชื่อวิทยาศาสตร์**: ตรวจทุกชื่อในระบบกับ GBIF แล้วดาวน์โหลดรายงานชื่อที่ต้องแก้ (ไม่แก้ข้อมูลในฐานข้อมูล)

ผู้เข้าชมทั่วไปดูข้อมูลได้โดยไม่ต้องล็อกอิน ส่วนการเพิ่ม แก้ไข นำเข้า และพิมพ์ป้ายทำได้เฉพาะผู้ดูแล (admin) และระบบไม่มีการสมัครสมาชิก

## เทคโนโลยีที่ใช้ (Tech Stack)

- [Next.js](https://nextjs.org) 16 (App Router) และ React 19 เขียนด้วย JavaScript
- [Tailwind CSS](https://tailwindcss.com) v4
- [Supabase](https://supabase.com): ฐานข้อมูล PostgreSQL, Auth และ Storage
- [Leaflet](https://leafletjs.com) และ leaflet.markercluster สำหรับแผนที่ ใช้แผนที่ฐานจาก OpenStreetMap
- [GBIF API](https://techdocs.gbif.org) สำหรับตรวจชื่อและข้อมูลชนิดพันธุ์
- qrcode สำหรับสร้าง QR code และ SheetJS (xlsx) สำหรับอ่านไฟล์ Excel
- three.js และ React Three Fiber สำหรับภาพพื้นหลังสามมิติ (โหลดเฉพาะจอกว้าง)
- Deploy บน [Vercel](https://vercel.com)

## ติดตั้งและรันในเครื่อง (Getting Started)

ต้องมี Node.js เวอร์ชันที่ Next.js 16 รองรับ (20.9 ขึ้นไป)

```bash
npm install
cp .env.example .env.local   # แล้วใส่ค่าจริงใน .env.local
npm run dev
```

เปิด <http://localhost:3000>

ตัวแปรใน `.env.example`:

| ตัวแปร | จำเป็น | ความหมาย |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | ใช่ | URL ของโปรเจกต์ Supabase (Project Settings → API) |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ใช่ | anon key (เปิดเผยได้ ข้อมูลป้องกันด้วย RLS) |
| `NEXT_PUBLIC_SITE_URL` | แนะนำ | URL หลักของเว็บ ใช้สร้างลิงก์ใน QR code (ไม่มี `/` ท้าย) ถ้าเว้นว่างจะใช้ origin ของหน้าที่เปิดอยู่ |
| `NEXT_PUBLIC_MAP_TILE_URL` | ไม่ | tile ของแผนที่ (ค่าเริ่มต้น OpenStreetMap) |
| `NEXT_PUBLIC_FORWARD_GEOCODING_URL` | ไม่ | บริการค้นพิกัดจากชื่อสถานที่ (ค่าเริ่มต้น Nominatim) |
| `NEXT_PUBLIC_ELEVATION_URL` | ไม่ | บริการความสูงจากระดับน้ำทะเล (ค่าเริ่มต้น Open-Meteo) |

ห้าม commit ไฟล์ `.env.local` และห้ามใส่ค่าที่เป็นความลับ (เช่น service role key) ในตัวแปร `NEXT_PUBLIC_` เพราะตัวแปรเหล่านี้ถูกส่งไปที่เบราว์เซอร์

## ตั้งค่าฐานข้อมูล (Database Setup)

ไฟล์ SQL อยู่ใน `supabase/sql/` ให้รันใน Supabase Dashboard → SQL Editor **ตามลำดับเลขหน้าชื่อไฟล์** และอ่านคอมเมนต์ต้นไฟล์ก่อนรันทุกครั้ง

1. `01_search_and_facets.sql`: คอลัมน์ `search_text` สำหรับค้นหา, index และฟังก์ชัน `get_plant_facets()` สำหรับสถิติและตัวเลือกตัวกรอง
2. `02_cleanup_profile_policies.sql`: ลบ policy ของตาราง `profiles` ที่ซ้ำกัน
3. `03_coordinate_source.sql`: คอลัมน์ `coordinate_source` (`manual` / `geocoded`) และ `coordinate_uncertainty_m` ตามแนว Darwin Core
   **ต้องรันก่อนใช้** หน้าเพิ่ม/แก้ไขพรรณไม้ และการเติมพิกัดอัตโนมัติ (ถ้ายังไม่รัน การบันทึกจะแจ้งให้รันไฟล์นี้ก่อน)
   ส่วน C ของไฟล์ตรวจด้วยว่าคอลัมน์ `id` มี default เพราะหน้านำเข้าไม่ได้ส่ง `id`

ไฟล์เหล่านี้ปรับเพิ่มบนโปรเจกต์ที่มีตาราง `plants`, `profiles` และ Storage bucket `plant-images`, `avatars` อยู่แล้ว

## ตั้งผู้ดูแลระบบ (Admin Setup)

1. Supabase Dashboard → Authentication → Users → **Add user** แล้วสร้างผู้ใช้ด้วยอีเมลและรหัสผ่าน
2. แก้ **app_metadata** ของผู้ใช้นั้นให้มี `{"role":"admin"}` (เช่นใน SQL Editor:
   `update auth.users set raw_app_meta_data = raw_app_meta_data || '{"role":"admin"}' where email = '<อีเมล>';`)
3. Authentication → Sign In / Providers → ปิด **Allow new users to sign up** เพื่อไม่ให้มีการสมัครสมาชิกเอง

ผู้ใช้ที่ไม่มี `role` เป็น `admin` จะเข้าหน้า `/account` ไม่ได้ (ระบบจะออกจากระบบให้และพาไปหน้าเข้าสู่ระบบ)

## นำเข้าข้อมูลจาก Excel (Importing)

หน้า `/account/plants/import` แท็บ “นำเข้าข้อมูล (Excel/CSV)”

1. ดาวน์โหลดเทมเพลต .xlsx (ชีต `plants` สำหรับข้อมูล และชีต `คำอธิบาย` บอกช่องบังคับและค่าที่ยอมรับ) หรือใช้ไฟล์เดิมที่มีหัวคอลัมน์ `PNU no.`, `Artificial group`, `Family`, `Botanical name`, `Collector`, `Collector no.`, `Locality/NP/Province`
2. เลือกไฟล์ ระบบอ่านทุกชีตรวมกัน ทำความสะอาดข้อมูล แล้วคัดแถวออกตามลำดับ: แถวว่าง → PNU ไม่ถูกต้อง → PNU ซ้ำในไฟล์ (คัดทุกแถวของเลขนั้น) → PNU มีในระบบแล้ว → ข้อมูลไม่ครบตามช่องบังคับที่ติ๊ก (ค่าเริ่มต้น 6 ช่อง: ชื่อวิทยาศาสตร์, วงศ์, กลุ่มพืช, ผู้เก็บ, เลขผู้เก็บ, สถานที่เก็บ; กลุ่มพืชที่ไม่อยู่ในรายการที่ยอมรับ เช่น “ลงทะเบียนแล้ว” ถือว่าไม่มีค่า)
3. ดาวน์โหลดรายงาน Excel เก็บไว้ก่อน (ชีต สรุป / คัดออก / PNU ซ้ำ / คำเตือน) เพื่อให้เจ้าหน้าที่แก้แถวที่ถูกคัดออก
4. กด “นำเข้า N รายการ” ระบบส่งทีละ 500 รายการ กดหยุดได้ (หยุดหลังชุดปัจจุบัน) จบแล้วดาวน์โหลดรายงานรวมผลการนำเข้าได้
5. กด “ตรวจใหม่” เพื่ออ่าน PNU จากฐานข้อมูลอีกครั้ง แถวที่นำเข้าแล้วจะย้ายไปอยู่ “PNU มีในระบบแล้ว” อัปไฟล์เดิมซ้ำจึงไม่สร้างข้อมูลซ้ำ

แนะนำให้รันส่วน E ของ `01_search_and_facets.sql` (unique index บน `pnu_no`) ก่อนนำเข้าจำนวนมาก เพื่อให้ฐานข้อมูลกัน PNU ซ้ำได้จริงเมื่อมีผู้เพิ่มรายการระหว่างนำเข้า

## เติมพิกัดอัตโนมัติ (Geocoding)

ต้องรัน `03_coordinate_source.sql` ก่อน

- หลังนำเข้าเสร็จ ระบบเริ่มเติมพิกัดให้รายการที่เพิ่งนำเข้าเอง และมีปุ่ม “เติมพิกัดให้รายการที่ยังไม่มี” ในแท็บ “เติมพิกัด / ตรวจชื่อ” สำหรับข้อมูลเดิม
- ค้นด้วย Nominatim (OpenStreetMap) ครั้งเดียวต่อชื่อสถานที่ ไม่เกิน 1 คำขอต่อวินาทีตามนโยบายการใช้งาน ชื่อสถานที่ประมาณ 500 ชื่อจึงใช้เวลาราว 10–25 นาที
- ลำดับการค้น: ข้อความเต็ม → ส่วนที่เจาะจงคู่กับจังหวัด → จังหวัดอย่างเดียว (ข้อความที่ระบุประเทศอื่น เช่น Cambodia จะค้นในประเทศนั้น) และแก้คำสะกดผิดที่พบบ่อยจากตาราง `lib/localityFixes.js` ก่อนค้น
- ชื่อสถานที่ที่ค้นไม่เจอ เพิ่มกฎใน `LOCALITY_QUERY_RULES` (`lib/localityFixes.js`) ให้ค้นด้วยข้อความที่กำหนดแทน วิธีเพิ่มกฎอยู่ในคอมเมนต์ของไฟล์ ผล “หาไม่เจอ” ไม่ถูกเก็บไว้ในเบราว์เซอร์ เพิ่มกฎแล้วกด “เติมพิกัดให้รายการที่ยังไม่มี” อีกครั้งได้เลย
- บันทึกเฉพาะรายการที่ยังไม่มีพิกัด (`latitude is null`) เป็น `coordinate_source = 'geocoded'` พร้อม `coordinate_uncertainty_m` (ครึ่งเส้นทแยงของกรอบผลลัพธ์ ต่ำสุด 1 กม.) ความสูงจาก Open-Meteo (บริการเดียวกับหน้าแก้ไข) วัดที่จุดพิกัดและใส่ทุกรายการที่ได้พิกัดซึ่ง elevation ยังว่าง เก็บเป็น “697 m” จุดในทะเลหรือไม่มีค่าไม่ใส่ หน้ารายละเอียดแสดงเป็น “697 ม. (โดยประมาณ)”
- ปุ่ม “เติมความสูงให้รายการที่ยังไม่มี” วัดความสูงจากพิกัดที่บันทึกไว้ให้รายการ geocoded ที่ยังไม่มีความสูง (ไม่ค้นชื่อสถานที่ใหม่ ไม่แตะรายการ manual)
- หยุดแล้วกดใหม่ ทำต่อเฉพาะรายการที่ยังไม่มีพิกัด จบแล้วดาวน์โหลดรายงาน Excel (ผลต่อชื่อสถานที่ พิกัด ระดับความแม่นยำ และ PNU ที่เกี่ยวข้อง)
- หน้ารายละเอียดแสดงวงกลมรัศมีความคลาดเคลื่อน “พิกัดโดยประมาณจากชื่อสถานที่ (±X กม.)” และป้ายพิมพ์/PDF ไม่พิมพ์พิกัดและความสูงของรายการเหล่านี้
- เมื่อ admin แก้พิกัดในหน้าแก้ไข รายการจะเปลี่ยนเป็น `manual`

## รายงานชื่อวิทยาศาสตร์ (Name Report)

แท็บ “เติมพิกัด / ตรวจชื่อ” → “ตรวจชื่อวิทยาศาสตร์ทั้งหมด”

- ตรวจทุกชื่อที่ไม่ซ้ำกับ GBIF พร้อมกันไม่เกิน 4 ชื่อ ผลแบ่งเป็น ok / synonym / spelling / genus_only / not_found / error
- รายงานอย่างเดียว ไม่แก้ข้อมูลในฐานข้อมูล ผลที่ตรวจแล้วเก็บในเบราว์เซอร์ หยุดหรือปิดหน้าแล้วกดใหม่จะทำต่อจากเดิม (มีปุ่มล้างผลเพื่อเริ่มใหม่)
- ดาวน์โหลดรายงาน Excel เฉพาะชื่อที่ไม่ใช่ ok: ชื่อเดิม ผล ชื่อที่แนะนำหรือชื่อที่ยอมรับ วงศ์เดิม วงศ์ตาม GBIF จำนวนรายการ PNU และลิงก์ GBIF

## ทดสอบ (Testing)

```bash
npm run test:gbif
```

ตรวจการเทียบชื่อวิทยาศาสตร์กับ GBIF (`lib/gbif.js`) ด้วยชื่อตัวอย่างจริง ต้องต่ออินเทอร์เน็ต

```bash
npm run build && npm start      # หรือ npm run dev
npm run test:gbif-species       # อีกหน้าต่างหนึ่ง
```

ตรวจ API `/api/gbif/species` ของเซิร์ฟเวอร์ที่รันอยู่ (ค่าเริ่มต้น `http://localhost:3000` เปลี่ยนได้ด้วย `BASE_URL=... npm run test:gbif-species`)

```bash
npm run test:label-pdf
```

สร้าง PDF ป้ายด้วยโค้ดเดียวกับปุ่ม “ดาวน์โหลด PDF” แล้วตรวจข้อความภาษาไทย ขนาดป้าย QR และป้ายของรายการพิกัดโดยประมาณ (ต้องไม่พิมพ์พิกัดและความสูง)

ทุกคำสั่งจบด้วย exit code 1 ถ้ามีข้อใดไม่ผ่าน

## ล้าง cache ข้อมูล GBIF (Clearing the GBIF Cache)

ข้อมูลจาก GBIF ถูก cache ไว้ฝั่ง server 7 วัน ถ้าต้องการให้ดึงใหม่ทันที:

- **บน Vercel**: Project → Settings → Data Cache → **Purge Everything**
- **ในเครื่อง**: หยุดเซิร์ฟเวอร์ ลบโฟลเดอร์ `.next/cache` แล้วรันใหม่
